# Five-minute demo script

This walkthrough can use either the desktop dashboard or the browser control center. Both connect to real SUMO runs; the browser scene is procedural and visualizes live vehicle positions and signal state.

To use the browser dashboard, start the API and Vite in separate terminals:

```bash
PYTHONPATH=. .venv/bin/python3 -m Traffic.api --host 127.0.0.1 --port 8000
npm --prefix Project/trafficSignal/web run dev
```

Open `http://127.0.0.1:5173`. Follow the controls below in either interface. The browser also provides a quality selector, a one-click 60-second balanced demo, live run progress, and CSV/JSON downloads.

## 0:00–0:45 — Introduce the experiment

Launch the desktop application:

```bash
PYTHONPATH=. .venv/bin/python3 Project/trafficSignal/main.py
```

Say: “This is a SUMO-backed intersection simulator. The fixed and adaptive controllers receive the same generated demand and seed. The adaptive controller samples queue lengths and induction-loop flow counts.”

## 0:45–1:30 — Configure

Select **Head-to-Head Comparative Benchmark**, choose **Balanced**, set a 120-second duration, and leave SUMO-GUI unchecked for a quick run. The scenario menu also includes heavy north–south, sudden surge, and rush hour. Point out the simulation controls and the live queue and integrated-delay charts.

Mention **Space** pauses/resumes and **R** stops the current run and clears the view. The Resume button offers the same action as Space when paused.

## 1:30–3:30 — Run the comparison

Click **Run Simulation**. Fixed and adaptive run simultaneously in separate SUMO sessions, stepping at the same simulation time against identical seeded route inputs. Explain that the two chart streams show live SUMO telemetry; no prerecorded data is used. The status log records adaptive timing decisions, including which flow estimate source was used.

## 3:30–4:30 — Read the outcome

Read the two benchmark curves and the completed-run summary. Mean queue is the time-series average of halting vehicles. Accumulated delay is the trapezoidal integral of queue length in vehicle-seconds. Mean trip travel time averages completed trips only. Completed trips counts vehicles that reached their destination. Negative change vs fixed means adaptive performed worse.

The current 120-second balanced seed-42 six-class run reported mean wait of 3.95 s fixed vs 3.21 s adaptive, delay of 812.0 vs 711.0 veh·s, mean queue of 6.79 vs 5.95, and 31 vs 32 completed trips. State that these are one measured run, not a guarantee across demand conditions.

Other 120-second seed-42 runs produced these measured outcomes:

| Scenario | Mean wait fixed → adaptive (s) | Delay fixed → adaptive (veh·s) | Mean queue fixed → adaptive | Trips fixed → adaptive |
|---|---:|---:|---:|---:|
| Heavy N–S | 4.91 → 3.20 | 1772.5 → 1263.5 | 14.83 → 10.58 | 40 → 50 |
| Sudden surge | 2.81 → 2.44 | 1003.5 → 973.5 | 8.54 → 8.25 | 35 → 38 |
| Rush hour | 3.11 → 2.52 | 772.5 → 689.0 | 6.52 → 5.82 | 28 → 30 |

Across these four seed-42 runs adaptive improved the listed metrics. That is limited evidence; use `--seed` to explore other arrival schedules and report regressions as well.

Balanced-demand checks with other seeds demonstrate why the result must be qualified:

| Seed | Mean wait fixed → adaptive (s) | Delay fixed → adaptive (veh·s) | Mean queue fixed → adaptive | Trips fixed → adaptive |
|---:|---:|---:|---:|---:|
| 1 | 2.71 → 5.16 | 659.5 → 1051.5 | 5.53 → 8.79 | 32 → 25 |
| 7 | 3.43 → 1.12 | 785.5 → 340.0 | 6.58 → 2.86 | 30 → 43 |
| 21 | 2.83 → 2.69 | 645.5 → 613.5 | 5.42 → 5.13 | 39 → 37 |
| 77 | 3.29 → 3.27 | 742.5 → 744.0 | 6.21 → 6.22 | 28 → 28 |

For seed 1 adaptive was materially worse across those metrics; seed 77 delay and queue were marginally worse. These are individual 120-second runs and should not be treated as statistical proof. All figures in this table were rerun after introducing the six seeded SUMO vehicle classes.

## 4:30–5:00 — Show artifacts

Use **Export Results CSV** or open `Project/trafficSignal/results/comparison_balanced_42_120.csv` and `.json`. The JSON record contains scenario settings, both summary metric sets, percentage changes, and adaptive queue observations, detector rates, solver status, selected green splits, and decision reasons. Mention that the files are generated by the current simulation run.
